# Auto-LAMMPS 软件能力改进完整计划
**本地记忆、验证复用与批量研究整合版**

本轮以原始完整计划和本次 DSH 的 W 级联审计为基础，完善现有软件能力。核心目标是：

**用户用自然语言提出需求；Agent 自动找到过去可用的工作，复用资源、方法和验证，只为新增问题投入计算，持续完成研究与交付。**

Agent 继续编写原生 LAMMPS、Python 和研究脚本。软件负责记忆、资源、执行、验证、监视和成果保存。远程部署不纳入本轮；跨平台安装保留在整体交付计划中。

## 一、用户实际使用流程

完整流程调整为：

> 自然语言需求 → 自动检索本地记忆和资源 → 简短问答 → 展示可复用内容与新增工作 → 必要验证 → 正式计算或批量计算 → 监视与分析 → 交付 → 更新记忆。

用户只需要表达：

> 参考上次的 W 级联方案，再做20次独立重复，给我平均缺陷数量和误差范围。

Agent 自动读取上次的科学条件、势函数、输入、验证记录、分析方法及失败经验，并回复：

> 已找到上次通过验证的方案。这20次重复可以直接开展正式计算，沿用原有输出和分析流程；将使用独立随机种子，并增加统计汇总。

遇到新问题时，每轮集中询问两三项影响科学目标的选择。文件位置、工具参数、版本查询、资源检索和历史读取由 Agent 与软件完成。

README 保留唯一的固定安装提示词。日常研究方法通过 skill、MCP 初始化说明和阶段工具返回提供。

## 二、本地记忆与成套资源

### 1．软件保存自己的本地记忆

本地记忆（**Memory /ˈmeməri/**）保存在 Auto-LAMMPS 数据目录，Codex、DSH 和后台 Agent 使用同一份记录。关闭聊天、更换模型或重启服务后继续有效。

在现有 SQLite 数据库和原生文件目录上扩展，首版采用结构化条件、关键词和中英文同义词检索。

| 记忆内容 | 保存什么 | 怎样帮助下一次工作 |
|---|---|---|
| 当前研究 | 原始需求、已确认选择、阶段、待办、控制状态 | 换对话继续，无需重新说明 |
| 成功方法 | 原生脚本、分析方法、运行环境、适用条件和实际结果 | 找到可以直接采用或局部修改的工作 |
| 验证记录 | 检查对象、条件范围、程序版本、阈值、实际值和证据 | 决定哪些验证可以省去 |
| 失败经验 | 错误表现、触发条件、日志、原因判断、修正及验证结果 | 写脚本和提交前主动提醒 |
| 用户偏好 | 用户明确表达的目录、展示、通知和工作习惯 | 减少重复配置与询问 |
| 已有成果 | 数据、图表、轨迹、报告及其来源关系 | 直接追加分析，避免重复计算 |

每条记忆关联原任务和实际文件，包含适用条件、版本、状态及来源。大型轨迹继续保留在已有存储位置，记忆只保存索引与必要摘要。

### 2．记忆自动进入工作流程

以下时点自动检索相关记忆：

- 创建或接续研究。
- 选择势函数与计算环境。
- 编写或修改脚本。
- 制定验证方案与准备提交。
- 诊断失败、开展分析和后台接续。

首先返回少量最相关记录、复用理由、条件差异和原始证据入口，完整记录按需读取。

当前用户要求和任务控制状态优先。历史授权、预算和已撤销的规则保留为历史，不自动变成新任务的执行许可。

### 3．自动积累与纠正

- 阶段完成、失败、修正和结果核验后，服务自动保存事实；Agent 补充方法摘要和解释。
- 服务依据实际检查回执登记“已验证”。Agent 提出的新经验先保存为候选。
- 原因尚未确定的失败保留待查状态；修正通过后关联对应证据。
- 新证据推翻旧结论时，更新有效状态，并标记引用它的任务和成果。
- 用户可以要求“查看上次依据”“纠正这条经验”“以后不要采用这条建议”。
- 记忆随软件备份和恢复；同一用户的普通研究默认可以跨项目检索。作者参考和正式 B 按各自的访问范围检索。

### 4．资源库形成完整组合

继续复用旧资源库，资源记录关联：

**实际文件＋调用示例＋元素映射＋配套参数＋短程组合＋来源许可＋引擎版本＋适用条件＋验证与失败记录。**

本次 W 的势函数及短程配置作为首项整理对象。用户指定来源时先核对对应组合；普通研究允许学习有来源、符合许可的作者代码。

旧记录按实际证据导入：文件核验、运行完成和科学验证分别保存。已有错误不会因进入记忆库而获得“通过”状态。

## 三、验证复用、小计算与批量正式计算

### 1．每次先判断已有证据能覆盖什么

复用（**Reuse /ˌriːˈjuːz/**）分为三个结果：

| 判断结果 | 软件动作 |
|---|---|
| 当前条件已经被有效验证覆盖 | 直接进入正式计算准备，不新增预验证作业 |
| 部分条件发生变化 | 复用有效部分，只补变化涉及的验证 |
| 属于新的方法或缺少对应证据 | 从必要的小规模验证开始 |

“相似任务”用于发现经验；验证是否有效由条件匹配决定。可以复用的内容分别判断，例如势文件读取、环境启动、步长设置、输出解析和分析方法，各自保留验证范围。

验证记录明确保存固定条件、允许变化的参数及其范围。范围必须有依据，不因两个端点通过就自动认定所有组合通过。

### 2．只为缺项安排分级验证

| 层次 | 主要解决的问题 |
|---|---|
| 文件与静态检查 | 依赖、单位、元素映射、命令用法、输出要求及已知错误 |
| 极小体系贯通 | 真实环境运行、输出、重启、分析、绘图与归档 |
| 代表性小体系 | 关键作用条件、步长、短程行为和数值稳定性 |
| 正式尺寸短运行 | 正式几何、并行配置、内存、输出量和早期关键阶段 |

检索已有验证后，只执行仍有缺项的层次。能够接续的合格计算段继续使用。

新建大型任务推荐预验证预算为 **100 核时**，随方案确认，包含失败与取消。服务核对已用和待执行资源；不足时返回剩余问题，不自动扩大预算。

所有物理求值继续通过已记账 HPC。正式 B 保留独立的次数与隔离规则。

### 3．通过验证后直接批量执行

用户要求追加正式计算时：

- 增加独立重复次数、采用已经允许变化的随机种子：直接复用验证。
- 批量执行已验证的工况组合：分别关联对应记录，直接执行。
- 更换对话、Agent，或服务重启：继续使用有效记录。
- 修改绘图、报告或统计方法：复用计算数据，检查新的分析。
- 改变势、关键方法、环境或超出已验证条件：只补受影响检查。

验证匹配同时检查原生文件及其依赖。任务名称、输出目录、样本编号和已允许的种子变化，不使整套验证失效；未被识别的改动返回具体差异和需要检查的部分。

每个批次保存工况、样本、随机种子、验证来源和执行记录。新增独立重复产生新样本；既有轨迹可以复用于分析，不重复计作独立样本。

批量调用可中断恢复，重复请求返回原批次。每个作业继续进行运行监视和结果核验。

## 四、执行控制、科学检查与接口

### 1．把已知问题前移

扩展已有官方语法适配器，结合研究类型、实际引擎版本和记忆中的失败条件，检查当前方案。

对本次 W 案例，重点覆盖短程配置、时间步、积分与热浴分组、能量收支、真实物理时间、边界、输出字段和采样。检查返回实际覆盖内容、未确定项及下一步。

分析需求在计算前确定，并使用真实短运行输出贯通。优先修正现有 W 数据中的温度、阶段边界、注入能量、逐帧身份和周期几何问题，生成新的分析版本。

### 2．程序产生验证结论

检查程序和阈值在验证前固定。执行回执包含：

**输入及数据版本｜检查程序版本｜实际范围｜测量值｜阈值与依据｜判定。**

Agent 新写的检查程序先通过独立正反样本，再进入可复用检查库。成果登记引用实际回执，完成检查核对全部必需成果和最新有效结果。

历史自报检查保留来源；新版需要的检查根据已有证据补齐。

### 3．暂停、监视和异常处理

- 用户要求“先讨论”或“暂停”时，Agent 优先写入任务控制状态。
- 提交、队列、后台接续和实际派发核对同一版本；已在途提交单独对账。
- 计算节点按预定规则检查快速数值异常，保存现场和重启点。
- 后台沿用每60秒合并查询、长任务每5分钟可读摘要。
- 批量任务显示已完成、运行中、等待、失败及剩余数量，同时显示费用和最近证据时间。
- 确认共同设置缺陷后，暂停受影响的后续派发，更新对应验证记录；其他有效任务继续。
- 分析失败保留计算数据，只恢复失败部分。

### 4．接口和数据改动

| 接口 | 具体变化 |
|---|---|
| 记忆接口 | 增加检索、读取、记录候选经验、更正和停用；每次变更保留来源和版本 |
| 阶段引导 | `task_get` 返回相关记忆、已确认条件、可复用内容和当前缺项 |
| 资源接口 | 返回成套文件、配套关系和验证适用范围 |
| 验证接口 | 登记验证方案、执行检查、读取回执和比较条件差异 |
| 提交接口 | `run_prepare/run_submit` 关联当前有效验证；实际派发前重新核对 |
| 批次接口 | 准备、提交、查询和控制批次，保存每个样本与已有验证的关系 |
| 成果接口 | `artifact_register/completion_check` 使用检查回执判断交付状态 |

数据库增加记忆及版本、验证方案及回执、复用关系和批次成员记录，继续使用现有事务、操作编号和执行权机制。

升级前备份，提供旧库迁移与回退验证。旧实验数据库通过只读入口接入；记忆索引可从保留记录重建。

## 五、实施顺序、验收与交付

### 1．实施顺序

| 顺序 | 交付内容 | 完成条件 |
|---|---|---|
| P0 | 控制状态与结果核验修复 | 本次暂停、错误判据和不完整检查样本能被正确处理 |
| P1 | 本地记忆、成套资源和阶段引导 | 新对话自动找到过去工作、失败经验和相关文件 |
| P2 | 验证匹配与分级预验证 | 已覆盖条件直接复用，变化条件只补对应检查 |
| P3 | 批量执行与持续监视 | 追加独立样本直接运行，批次可暂停、恢复和跨会话接续 |
| P4 | 完整分析和用户验收 | 官方 DSH 完成新研究，Codex 接续、追加分析与交接 |

每项修改通过 Issue、分支、PR、自动检查和固定安装候选交付。同步更新 skill、工具说明、用户指南、开发手册和进度记录。

### 2．必须通过的场景

1. **首次新研究：** 一句话进入，经问答、资源检索、必要验证、正式运行和分析完成交付，开发者中途技术补充为零。
2. **同条件追加20次重复：** 自动检索已验证方案，新增预验证作业为零；20个样本身份独立、费用完整。
3. **跨项目复用：** 新任务自动找到相同方法和有效验证，不依赖用户记住旧任务编号。
4. **局部变化：** 改变一个关键条件，只补对应验证；无关验证和成果继续复用。
5. **不同材料或新势：** 找到可借鉴方法，同时准确识别尚未覆盖的部分。
6. **记忆纠正：** 旧经验被推翻或停用后，新任务不再按旧结论直接提交。
7. **证据变化：** 文件修改、依赖缺失或环境变化时，返回受影响项；不能沿用不匹配的回执。
8. **恢复与控制：** 换对话、重启、批次中断和提交回执丢失后正确接续；暂停确认后新增派发为零。
9. **成果检查：** 全部必需文件可打开、可追溯；已知错误宣告完成为零。
10. **备份迁移：** 在新数据目录恢复后，记忆、验证、资源关系和历史均可读取，执行前完成作业对账。

### 3．衡量实际增益

分别记录首次研究、复用研究和批量追加的：

- 预验证次数与核时。
- 正式计算失败成本。
- 模型调用、工具调用与人工介入。
- 从需求到正式提交的时间。
- 首次正式计算完整交付率。
- 全部发起研究的完成率及未进入正式计算的原因。

新增预验证必须说明它填补的具体缺项。复用收益通过实际对照和记账评估。

原计划的独立 Ni 验收、24项研究至少完成22项、12项保留任务至少完成11项、36次故障恢复、八类科学反例、双平台和七天监视继续作为整体交付要求。

**本轮最终交付：软件能够记住过去、主动找到可复用工作、准确复用验证，并让用户通过自然语言持续开展正式研究和批量计算。**
