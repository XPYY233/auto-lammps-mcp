# Local research memory and verification reuse

Accept a short natural-language request. Start with task_list/task_get or task_create. Read research_context before resource selection, editing, preflight, recovery and analysis. Ask two or three unresolved scientific choices together; retrieve paths, native syntax, versions and earlier records yourself. A historical authorization never authorizes a new task.

memory_search uses aliases and conditions within the task's access scope; memory_get gives evidence and correction history. An observed event or candidate lesson is not measured validation. Record proposed methods/failure explanations with memory_record. The service saves factual events and qualified checks; keep uncertain causes pending. Disable or correct disproved lessons without deleting history. memory_rebuild indexes earlier task events while preserving corrections.

Find complete potential/method combinations with resource_search/resource_get. resource_bundle links existing member files, native invocation, element mapping, short-range parameters, provenance, license and applicable conditions. Check actual members and revisions. Ordinary research may learn licensed author code. Formal B retains its separate source boundary.

Directly registered native files expose file_root and files for resource_file_read. A bundle returns each member's current file check as well as its metadata version. Require files_current before using a member. For a measured failure, memory retains the actual value, criterion, receipt and source hashes as observed evidence; its physical explanation remains a candidate until tested. Keep a user's reference combination distinct from the combination actually used in an earlier job.

Freeze all research inputs using project_snapshot(paths=[...]); exclude results. validation_plan components list id, scope, files, condition_keys, checks. Include every dependency and every scientific condition. Keep immutable engine/version evidence in the input bundle and conditions. Separate numerical, environment, output and geometry dependencies so a changed condition affects the right component.

Before the first validation_plan, call environment_capture with the engine and launcher commands actually used by the native entry, plus absolute external plugin/container/runtime files. This reads executable bytes and resolved shared libraries without invoking the engine or adding a physical job. Read operation_get, then pass its result.id as runtime_id. A reuse_from plan inherits that identity; capture again when selecting a new runtime. The service repeats the byte comparison before dispatch and on the compute node before starting the native script. The completed run's collected .alm-runtime.json is included automatically in physical-component checks. Missing or changed runtime files affect environment/numerics/outputs; retain unaffected static checks. This identity record does not itself establish scientific validation.

Always call validation_match before arranging new physical checks. ready=true permits production; a partial match specifies the remaining components. A new plan can use reuse_from to retain identical, still valid measured components. New material, potential, method or unrecognized edits require matching their real differences. Do not infer a validated parameter range from two endpoints.

Explain the actual returned component list to the user. Do not turn a potential or parameter change into a blanket instruction to repeat all checks. Keep reusable native includes separate from changed condition files so dependency matching can preserve valid work. For each new physical check, state the missing component and the evidence it will supply.

For missing evidence use: static files → tiny full workflow → representative high-force/temperature case → formal-size short run. Choose scope by missing component, not a mandatory repeat ladder. Each layer has native inputs and a plan. Retain good continuous segments and continue via native restart. Preflight stage uses run_prepare(validation_id=...,stage='preflight'). All physics remains accounted HPC. Default budget is 100 core-hours across the task's plans, failures and cancelled work; running reservations count until actual final accounting arrives. Save the user's agreed budget and authorization.

Physical validation_check requires a completed run and its collected data_root='runs/<run_id>'. The service compares collected hashes and executes the frozen component criteria. Production uses stage='production' and requires static/environment/numerics/outputs coverage. environment_check is the bootstrap environment probe, not a substitute for research validation.

For independent repeats, declare one native integer seed variable, its file and method-supported min/max. batch_prepare samples are [{sample_id,seed}]. It generates immutable native snapshots, checks the original verification and adds no preflight jobs. Use batch_submit under current authorization. For multiple previously verified conditions, prepare each condition's batch against its own plan. Reanalysis retains original sample identities.

Read batch_get for counts, sample identities, latest evidence and cost. User pause/first discuss: write task_control first; use batch_control for one group. Resume only within current user intent. In-flight submissions are reconciled separately. Confirmed shared setup defects use validation_control; preserve failures and costs. Repeating the same op_id returns the original result.

Node monitor criteria are fixed in validation_plan(monitor=[...]). Use thermo path, block, energy_column and max_abs_drift. This is phase-specific energy balance; account for thermostats, external work and injection when choosing the measured quantity and criterion. Use native restart output and flushed logs. Do not treat real melting or defect spikes as numerical failure. The official adapter retrieves dt/reset, ZBL and temperature definitions for the actual engine version.

check_run produces measured receipts for file/csv/json/thermo/trajectory/energy_jump checks. Use basis and unit for criterion provenance. Inspect check_get measurements, coverage and current_passed. Agent-defined analysis checkers first run distinct positive and negative data through analysis_submit; checker_register freezes the same program hash and JSON criteria after both match. checker_check verifies later outputs. Change a checker only by qualifying the new version.

artifact_register checks=[{receipt_id:...}] links the service receipt to the actual artifact. Legacy passed booleans remain historical claims. completion_check needs every required artifact, current data and valid checks. Export includes research history; whole-service backup preserves executable validation and batch relationships. After restore, reconcile before recovery_activate.
