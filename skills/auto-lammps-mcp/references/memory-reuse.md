# Local research memory and verification reuse

Accept a short natural-language request. Start with task_list/task_get or task_create. Read research_context before resource selection, editing, preflight, recovery and analysis. Ask two or three unresolved scientific choices together; retrieve paths, native syntax, versions and earlier records yourself. A historical authorization never authorizes a new task.

memory_search uses aliases and conditions within the task's access scope; memory_get gives evidence and correction history. An observed event or candidate lesson is not measured validation. Record proposed methods/failure explanations with memory_record. The service saves factual events and qualified checks; keep uncertain causes pending. Disable or correct disproved lessons without deleting history. memory_rebuild indexes earlier task events while preserving corrections.

Find complete potential/method combinations with resource_search/resource_get. resource_bundle links existing member files, native invocation, element mapping, short-range parameters, provenance, license and applicable conditions. Check actual members and revisions. Ordinary research may learn licensed author code. Formal B retains its separate source boundary.

Directly registered native files expose file_root and files for resource_file_read. A bundle returns each member's current file check as well as its metadata version. Require files_current before using a member. For a measured failure, memory retains the actual value, criterion, receipt and source hashes as observed evidence; its physical explanation remains a candidate until tested. Keep a user's reference combination distinct from the combination actually used in an earlier job.

Freeze all research inputs using project_snapshot(paths=[...]); exclude results. validation_plan components list id, scope, files, condition_keys, checks. Include every dependency and every scientific condition. Keep immutable engine/version evidence in the input bundle and conditions. Separate numerical, environment, output and geometry dependencies so a changed condition affects the right component.

Before the first validation_plan, call environment_capture with the engine and launcher commands actually used by the native entry, plus absolute external plugin/container/runtime files. This reads files without starting the engine. Read operation_get and pass result.id as runtime_id. Login discovery verifies engine/launcher/explicit files; login hosts may have different system libraries. Accounted preflight records the actual compute-node engine and libraries in .alm-runtime.json. Physical checks bind that complete collected receipt to the job. Production compares the verified compute runtime before starting its native entry; an actual change returns file differences. Retain unaffected static checks. Discovery alone does not establish scientific validation.

Always call validation_match before arranging new physical checks. ready=true permits production; a partial match specifies the remaining components. A new plan can use reuse_from to retain identical, still valid measured components. New material, potential, method or unrecognized edits require matching their real differences. Do not infer a validated parameter range from two endpoints.

Explain the actual returned component list to the user. Do not turn a potential or parameter change into a blanket instruction to repeat all checks. Keep reusable native includes separate from changed condition files so dependency matching can preserve valid work. For each new physical check, state the missing component and the evidence it will supply.

For missing evidence use: static files → tiny full workflow → representative high-force/temperature case → formal-size short run. Choose scope by missing component. Each layer has native inputs and a plan. Retain good continuous segments and continue via native restart. Preflight uses run_prepare(validation_id=...,stage='preflight'). All physics remains accounted HPC. Recommend 100 core-hours when appropriate, then save the user's confirmed cap in policy.preflight_core_hours and their words in preflight_budget_authorization. An estimate is distinct from this cap. A job reserves cores × wall_seconds / 3600 until actual accounting arrives; use a realistic maximum duration for each layer. Failures and cancellations count across all plans. A new plan cannot raise the cap. If the remaining budget is insufficient, return the missing work and request an explicit change.

Use the returned revision for the next mutation. An exact repeated intent returns the original run. Changing validation plan or stage must produce the correct new binding. Replace an unsubmitted prepared/cancelled/staging_failed record with a new intent and supersedes=old run_id; retain the same scientific sample_id. Query and reconcile an in-flight or unknown job before considering another submission. Do not rename samples to escape duplicate handling.

Physical validation_check uses a terminal accounted run and collected data_root='runs/<run_id>'. Failed/cancelled jobs can supply complete usable parts. Corrected criteria can reuse matching prior run data; changes to scientific inputs still require the affected checks. The service compares collected hashes and executes the component criteria. Production uses stage='production' and requires static/environment/numerics/outputs coverage. environment_check is the bootstrap environment probe.

For independent repeats, declare one native integer seed variable, its file and method-supported min/max. batch_prepare samples are [{sample_id,seed}]. It generates immutable native snapshots, checks the original verification and adds no preflight jobs. Use batch_submit under current authorization. For multiple previously verified conditions, prepare each condition's batch against its own plan. Reanalysis retains original sample identities.

On continuation, task_get exposes recent batches; use batch_list for older batches without asking the user for identifiers. Read batch_get for counts, sample identities, latest steps/physical time, evidence time and cost. Missing accounting remains explicitly unknown. Read run_get or batch_get(include_details=true) for full evidence. A batch with all jobs finished proceeds to analysis and completion_check. User pause/first discuss: write task_control first; use batch_control for one group. Resume only within current user intent. In-flight submissions are reconciled separately. Confirmed shared setup defects use validation_control; preserve failures and costs. Repeating the same op_id returns the original result.

Choose task-specific criteria from the research goal, actual engine documentation, resource combinations and prior evidence. No universal energy/time-step tolerance is supplied. Record basis and unit; check output precision and normalization. Exceeding an old threshold establishes that observation, not a physical cause. Reconsider a criterion using evidence and record rationale in a new plan. Preserve the original measurements and costs.

Node monitor criteria are fixed in validation_plan(monitor=[...]). Prefer phase={fix_id:'collision',style:'nve'} over counting blocks. Keep echo log and native stage markers in the input; log_phases reads actual fixes, groups, time steps, units and normalization. Matching consecutive runs retain their energy baseline across time-step changes; different integration phases receive separate baselines. Account for thermostats, external work and injection. Raw energy with a known exchange returns an applicability issue; use the appropriate energy balance or a task-specific basis with balance=task_specific. Unknown/custom methods can use a qualified native checker. Use native restart output and flushed logs. Real melting/defect spikes are not automatically errors.

Each check has role=required (default), advisory or candidate. Node action=warn is the default; set action=stop only for a justified rapid numerical failure. Candidate/advisory checks never terminate the simulation. An inapplicable monitor reports the issue without stopping the engine; the corresponding required validation remains unproven. An output/check issue affects its component, preserving valid calculations, other measurements and their receipts. An optional exploratory component uses required=false. Pause a whole task only on user control or a shared defect affecting its remaining work.

When useful, the host Agent may propose several candidate methods in parallel, writing separate native files and checking the same retained data with role=candidate. This does not require parallel HPC jobs. Use validation_compare to inspect criteria, measurements and differences; assemble the final components with validation_plan(reuse_sources=[...],rationale=...). Merge on scientific applicability and evidence, not majority vote or selecting the easiest pass. Only the task owner commits the final plan. Common fixes and analysis may proceed autonomously within the current scientific scope and budget; ask the user about scientific choices that remain unresolved.

check_run produces measured receipts for file/csv/json/thermo/trajectory/energy_jump checks. Use basis and unit for criterion provenance. Inspect check_get measurements, coverage and current_passed. Agent-defined analysis checkers first run distinct positive and negative data through analysis_submit; checker_register freezes the same program hash and JSON criteria after both match. checker_check verifies later outputs. Change a checker only by qualifying the new version.

To use that native checker for a validation component, add checker_id, include the program in files, and keep checks=[{...registered criteria,path:'metrics.json'}]. Run analysis_submit on the collected data using input_bindings, then validation_check with analysis_operation_id. The service verifies program identity, fixture evidence, raw run inputs and measured output. Changing only the analysis/check does not itself require another physical calculation.

artifact_register checks=[{receipt_id:...}] links the service receipt to the actual artifact. Legacy passed booleans remain historical claims. completion_check needs every required artifact, current data and valid checks. Export includes research history; whole-service backup preserves executable validation and batch relationships. After restore, reconcile before recovery_activate.
