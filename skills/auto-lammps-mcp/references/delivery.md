# Analysis and delivery

Choose analyses from the scientific question and actual files. Separate averages from atom-resolved evidence, independent samples from frames, new samples from retries, program errors from physical anomalies. Preserve definitions, units, statistical windows, sample identities and uncertainty. Keep rejected hypotheses and previous plots.

Inspect actual data headers and sample rows before processing a full trajectory; data_inspect exposes thermo blocks and trajectory columns. Resolve fields by column name and check row widths. Match curves and structures through their recorded timestep and atom IDs. Derive averaging windows and normalization from the native definitions: a block average divided by an endpoint value is generally an approximation, so record that approximation when using it. Keep each reported event's exact sampled frames alongside any wider view chosen for visualization.

Read the real box-bound format before parsing it. Compare atom identity and type mappings by ID across frames; output rows may be reordered while every atom is retained.

Use existing plotting and structure/trajectory viewers. Show important plots inline when the host supports them, plus data/script/trajectory links. Register real artifacts and their sources and checks. `completion_check` reports missing requirements; continue those items. Export a package that a colleague can inspect and continue using.

Record a failed scientific review with passed=false and its evidence, using the affected artifact path and full requirement list. The latest registration for that path is current; its failed checks reopen the linked deliverables, while previous verdicts remain readable. Correct the scientific content and register the new review before checking completion. Distinguish a globally averaged temperature from a spatially resolved temperature, box bounds from box lengths, and measured structural changes from proposed mechanisms.

In official DSH, use its present tool with files=[{path: absolute_path, description: short_description}] to give the user a plot and handoff ZIP. Clicking the filename previews a supported image in DSH's side panel; its app button opens the original file in the normal desktop viewer. This works with the existing text model: verify numerical outputs and file content, then present the files. Use image reading when the selected model declares image input. Explain how to open the result directly; model input capabilities and user-visible previews are separate. In Codex, show supported images inline or open the actual file in its preview panel.

For existing-data analysis: import the complete source directory; write a native Python script under the task's project_path; call analysis_submit with project-relative inputs and output names; release the lease while the queue runs. Its working directory is analysis/<operation_id>/ and inputs keep their relative names. Read operation_get for output paths and logs, use artifact_preview for the actual plot, then register checks and requirement links. Use help(method) for these exact contracts before inspecting implementation files. All long-running methods return operation_id; a waiting queue needs its task lease released.

For handoff, project_export returns a ZIP outside the project tree. Give the user that returned path directly; project_import accepts it in a new task and preserves original records. For backup, release leases, call backup_create and retain its SHA-256 receipt. A restored service waits for recovery_activate until the original controller has stopped.

For paper reproduction, determine scope from published results first. Keep author source, reference answers and independent evaluation access separate. Retrieve resources through existing authorized connections.

Reuse earlier analysis outputs through analysis_submit(input_bindings={"data/input.csv":"analysis/<earlier-operation>/data/input.csv"}, inputs=[]). The key is the path the native script reads in its working directory; the value is an existing project file. The service retains the source hash and creates an independent editable copy. Read the returned receipt before selecting output paths.

For large historical projects, project_optimize queues sharing of unchanged data blocks with existing verified snapshots on supported volumes. Release task ownership while it runs. Every file path, byte content, mode, modification time and prior attempt remains. Files with extended access rules or without suitable snapshots/support stay in place. Read the receipt's path list and measured free space; archives retain all files and need their own disk space.

Check derived units from equations: covariance carries the product of its operands' units. LAMMPS centro/atom sums squared neighbor-vector lengths; in metal units the unnormalized value is Å², while a fraction of atoms above a stated threshold is dimensionless. stress/atom has pressure-times-volume units, so document the chosen volume normalization. A single instantaneous sample cannot validate a time average. State which stress measure and averaging window each derived column represents. See the current [centro/atom](https://docs.lammps.org/compute_centro_atom.html), [stress/atom](https://docs.lammps.org/compute_stress_atom.html) and [ave/time](https://docs.lammps.org/fix_ave_time.html) definitions.

While a large project_export is running, read operation_get.progress (also present in task_get work and task_records). Show phase, files_done/files_total, input_bytes_done/input_bytes_total, archive_bytes and observed_at. Counts describe the current export phase; archive checksum verification follows packing. On interruption read the retained partial archive path, resume the task and request a new export. Keep the earlier archive.

For narrative statistics, compare each displayed number and its definition to the actual data, including population versus sample standard deviation and the exact selected interval. A generated values table agreeing with a script does not establish agreement with the prose or PDF. Rebuild and inspect every changed delivery format.
