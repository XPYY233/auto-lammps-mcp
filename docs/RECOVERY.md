# 后台与恢复

schema 2 升级前在数据目录的 migrations 保存一致性旧库副本。完整备份包含记忆版本、验证、回执、批次和资源。回退使用旧安装与升级前数据库副本，新版数据另外保留；先停旧控制器，再在新目录恢复并对账。`memory_rebuild` 可从保留事件补建观察索引；已停用经验不重新启用。重启不会清除批次身份、种子、费用或验证引用。

macOS LaunchAgent 运行独立任务服务。MCP 与 CLI 连接同一服务，聊天退出后后台继续。数据库保存任务、事件、操作回执、执行意图、队列与阶段关系；普通目录保存科研文件，文件摘要对应输入快照。

`doctor.daemon.heartbeat` 返回本次服务的启动编号、启动时间和最近监视时间。每分钟的记录保留在事件历史中；重启产生新编号，便于核对离开期间是否持续运行。

后台 Agent、计算派发、具体数据处理和监视各自推进。Agent 等待导入、分析或导出时，处理队列继续执行；大文件上传时，其他分析也能完成。准备和上传每 30 秒保存阶段及证据时间，同一任务的文件修改仍通过操作权协调。

用户修改执行规则时，尚未派发的任务回到准备状态。Agent 使用最新规则重新登记提交，旧规则的上传完成后会再次核对；已经开始派发的动作保留当时规则与历史。

| 状态或问题 | 处理 | 保留事实 |
|---|---|---|
| prepared | 已固定输入和环境，等待提交 | 快照、工况、样本和规则 |
| pending | 已接收要求，等待派发 | 授权和实际规则 |
| dispatching / unknown | 先按原名称核对远端 | 一次提交标记、原执行意图 |
| queued / running | 每 60 秒按集群合并查询 | 作业身份、证据时间、核算 |
| completed / failed | 回收文件并检查成果或诊断 | 原失败、输出、费用 |
| 连续两次查询失败 | 显示连接异常和最后确认时间 | 已确认状态 |
| 分析失败 | 修改脚本，建立新分析尝试 | 原计算结果与各次日志 |
| Agent 中断 | 保存待办与证据，重新接续 | 原目标、已否定修复、版本 |
| 服务重启 | 核对在途派发，接续可重复数据操作 | 作业身份和已完成结果 |

操作权有到期时间，旧 token 不能写入。暂停、恢复和停止检查任务版本。停止先保存意图，再取消远端作业；未知作业找回后继续取消。诊断、修改、分析与正式提交分别记录。SSH 凭据变化不改变任务保存的作业身份。

`task_get.executor` 显示当前操作权持有人和期限；`active_background` 显示正在执行的后台接续编号。后台等待分析时可能释放操作权，前台仍可通过该编号跟进进展，随后读取最新任务版本接续。

用户说“这项研究先由当前对话处理”时，调用 `task_background(enabled=false)` 暂停本任务后续自动接续。正在进行的一轮继续完成，回执列出对应编号；需要立即交接时先暂停任务，再读取当前工作后恢复。`task_get.automation` 显示本任务设置和后台服务是否启用。重新启用后接续已保存待办，其他研究保持原设置。

分析失败会保存 `analysis-receipt.json`。操作的 `error.evidence` 返回输入摘要、退出码、可直接交给 `file_read` 的日志路径、已有输出与缺项。脚本执行后失败标为 `partial`，准备阶段失败标为 `saved_needs_correction`。修正脚本后生成新的分析编号，原脚本副本、失败日志和部分数据保留。

大文件导入、快照和分析输入在支持的 macOS 文件系统上共享未修改的数据块；每份文件可独立编辑。其他文件系统采用完整复制。分析回执记录每个输入的复制方式与大小，原始摘要与历史持续保留。参见 [Apple 文件复制接口](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/clonefile.2)。

同一成果路径采用最近一次登记的检查结果。后续科学复核发现错误时，用 `artifact_register` 保存未通过的检查与证据，关联要求重新进入待交付；其他文件的通过记录不能抵消这项失败。修正内容并重新核验后，再登记当前结果。原通过记录、失败意见和修正过程持续保留。

## 升级与恢复

后台 Codex 使用官方自动审批审查入口。每轮保存真实工具调用记录；读取目标任务成功后才能记为接续验证通过。指定 expected_outputs 时还逐项检查产物和摘要。进程正常退出或返回一段文字都需要这些执行证据。

依据：[Codex CLI 参数说明](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。

保留固定版本环境和安装回执。升级前读取协议与数据库版本，备份数据库与项目；升级后验证工具调用、已有作业、后台恢复和文件完整性。协议不一致拒绝写入并提示接入同一版本。

回退命令为 `python3 scripts/install.py --rollback --host codex`，使用保留的上一版本重新连接服务，并切换 current。DSH 回退时选择 `--host dsh`，带上已有 runtime 和 profile。完成后读取 doctor 中的 installation_source、实际 Python 路径与任务记录。重复安装同一版本保留上一版本入口；安装器同时只允许一个流程修改连接。

安装器与后台共同协调本地处理。上传、分析或 Agent 接续仍在进行时，安装器先返回可接续回执，现有连接和工作指南保持可用。取得升级操作权后，新处理留在原队列，后台重启完成后继续推进。安装进程意外退出时，操作系统自动释放升级操作权。旧版本升级还核对已接受的派发与处理，原作业身份和远端运行继续保留。

回退使用保留的环境和兼容数据，核对原作业与费用。软件、用户数据和凭据分别管理。卸载先停止本项目 LaunchAgent，移除本项目 MCP 连接与 skill，研究目录由用户选择保留或迁移。

备份包含数据库一致性副本、内容文件、快照、项目、安装回执和导出包。恢复到独立目录后校验摘要，用当前对话读取历史任务，再核对远端作业。

调用 `backup_create(destination, op_id)` 后读取返回的操作编号。备份在独立队列中执行，保存数据库一致性副本、项目、内容快照、导出包和处理日志，回执包含完整文件摘要。备份前释放任务操作权。

恢复使用 `alm --home /new/state restore /backup/archive.zip --sha256 RECEIPT_SHA256`。新目录恢复后可启动服务读取任务，执行队列保持等待。确认原控制服务停止后，调用 `recovery_activate(previous_controller_stopped=true, op_id=...)`；本机原服务仍在响应时不会接续。原作业编号、失败、费用与需求都保留，工具连接按新目录重新安装。

## 共同问题

运行进度由同一次远端查询读取调度状态与默认日志的末尾片段，包含文件大小、修改时间、读取范围和完整热力学行。自定义日志用 `run_log` 分页读取。LAMMPS 的 Step、Time 与单位对应关系由原生输入及实际列名确定，参考 [thermo_style](https://docs.lammps.org/thermo_style.html) 和 [log](https://docs.lammps.org/log.html)。

确认公共环境或模板缺陷后，暂停受影响的新派发。修复重放最小失败输入、原失败样本与完整研究流程。两次修复没有新证据或一小时未定位时，转入共同原因与替代路径分析。每次失败、处理和验证写入审计记录。

导出大项目时，`operation_get.progress` 返回当前阶段、已处理/总文件数、已读取/总数据量、已写归档字节和证据时间；`task_get` 与工作记录显示相同进展。阶段依次为核对输入、归档、核对成果包、完成。暂停交接后保留部分归档入口，恢复时创建新操作，原失败保留。

耗时分析或导出已入队后，可调用 background_request 并把操作编号放入 after_operations，保存完成后的下一步。收到真实接续编号后即可结束当前模型轮次。程序等待前置操作完成或失败，再启动接续；暂停任务或关闭该任务后台仍然有效。expected_outputs 填具体项目文件路径。
