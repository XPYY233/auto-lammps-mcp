\section{Auto-LAMMPS MCP}


在 Codex 或 DeepSeek Harness 中，用自然语言完成材料模拟研究。



Agent /\allowbreak{}ˈeɪdʒənt/\allowbreak{}（智能体）直接编写 LAMMPS、Python 脚本，读取日志并修正；Auto-LAMMPS 负责项目保存、超算执行、后台监视、分析和成果交接。



当前开发候选加入本地记忆、验证复用和批量研究：用户可以说“沿用上次方案，再做20次独立重复”。Agent 检索过去工作，已覆盖条件直接准备正式批次，只为变化补充验证。具体安装版本与实测进度见交付记录。下面的固定安装提示词继续作为统一入口。



当前使用环境：macOS · Codex /\allowbreak{} 官方 DeepSeek Harness（DSH）· Slurm 超算。



复制安装提示词 · 开始第一项研究 · 查看后台进展 · 版本与进度 · 文档导航



\subsection{从这里开始}


1. 打开 Codex 或官方 DSH，进入能访问本机文件、执行命令的工作对话。

2. 复制下方完整安装提示词，粘贴到对话中。Agent 会读取给 Agent 的安装指南，识别环境并推进安装。

3. 按引导选择研究目录、已有超算连接和计算环境。安装完成后，选择新建研究、继续项目或分析结果。



安装会复用平台已有的模型设置。新电脑先登录所选 Agent 平台；需要提交计算时，配置自己的 Slurm 账号、远端工作目录和 LAMMPS 环境。已有结构、势函数或结果目录可以直接提供给 Agent。



\subsection{复制给 Agent 的安装提示词}

\begin{quote}\small

识别操作系统、当前 Agent 平台，以及你是否能够执行本机命令、安装插件和调用 MCP。\par
能安装插件时，优先安装包含工作指南和工具配置的插件。\par
有本机执行能力时，完成本地安装。已经接入服务时，先检查已有连接。\par
需要我切换会话或操作平台设置时，告诉我具体打开哪里、填写什么，并保存接续信息。\par

检查软件版本、真实安装位置、后台服务和平台连接。\par

复用已有可用安装，保留研究数据和其他软件配置。\par


3. 完成安装与平台接入\par
安装当前发布版本、科研工作指南、命令行、MCP 连接和持久后台。\par
使用安装器返回的真实路径继续工作。\par
安装后运行环境检查，并从当前 Agent 会话实际调用软件工具，确认我已经可以在这里使用它。\par


4. 引导我完成基本配置\par
先发现已有配置，再集中询问仍然缺少的内容：研究项目保存位置；超算连接、账号和计算队列；远端工作目录和已有 LAMMPS 环境；任务资源设置；后台自动接续和通知偏好。\par
提供推荐值，并用简短中文解释用途。已有配置让我直接选择；密码、密钥和验证码通过本机凭据入口或登录窗口填写。\par


5. 验证后台与恢复\par
检查后台服务、任务保存、通知和后台 Codex 接续能力。\par
保存配置进度，让我关闭对话后能够继续。\par
需要重新打开会话时，给我一句可以直接复制的接续提示词。\par


6. 带我完成第一次使用\par
配置完成后展示实际配置摘要，让我选择：新建研究、继续已有项目、分析已有结果。\par
如果我选择首次计算验证，先展示计算内容和资源设置。我说“开始”后，完成提交、进度反馈、数据回收、图表和结果文件。\par


7. 出错时继续处理\par
根据当前版本的帮助和检查结果定位问题。\par
告诉我已经完成什么、卡在哪里、下一步是什么。\par
保留有效配置和已有成果，从失败处恢复。\par


整个过程使用简短中文。每完成一个阶段告诉我结果；需要我操作时，一次只给当前必需的步骤。\par
完成后告诉我如何开始任务、查看进度、暂停或停止、查看结果，以及换一个对话继续研究。\par
\end{quote}

\subsection{安装固定版本}


\#\#\# 先选择同一套发布文件



从 Releases 选择已发布版本，记录标签、源码提交和安装包摘要。公开候选版本也显示在该列表中。README 的开发版本号说明当前源码进度，安装包版本以所选发布记录为准。



从该版本的发布附件取得 install.py、wheel、SHA256SUMS 和 release.json；核对安装器与 wheel 的 SHA-256。读取相同标签下的本指南和 skill，例如发布页的源码入口指向 blob/\allowbreak{}<tag>/\allowbreak{}docs/\allowbreak{}FOR\_\allowbreak{}AGENTS\_\allowbreak{}INSTALL.md。保存文件实际位置后继续安装。



若用户需要当前源码中的新增能力，先展示与发布包的具体区别，选择固定 Git 提交并记录验证状态。已有可用安装先检查，保留原任务和配置。



\#\#\# 使用发布 wheel



使用下载好的安装器及 wheel；下列路径与摘要由实际发布附件替换，host 选择当前平台：



\begin{quote}\small
python3 /\allowbreak{}absolute/\allowbreak{}path/\allowbreak{}install.py \textbackslash{}\par
  -{}-wheel /\allowbreak{}absolute/\allowbreak{}path/\allowbreak{}auto\_\allowbreak{}lammps\_\allowbreak{}mcp-VERSION-py3-none-any.whl \textbackslash{}\par
  -{}-sha256 VERIFIED\_\allowbreak{}WHEEL\_\allowbreak{}SHA256 -{}-host codex\par
\end{quote}


DSH 使用 -{}-host dsh，并添加下文的 -{}-dsh-runtime 与 -{}-dsh-profile。安装器检查 wheel 摘要后建立独立版本环境。



\#\#\# 使用固定源码



从仓库克隆并检出所选发布标签或完整提交，在这个干净的 Git 检出目录运行：



\begin{quote}\small
python3 scripts/\allowbreak{}install.py -{}-source . -{}-host codex\par
\end{quote}


源码安装通过 Git 保存确切提交身份；已有用户修改的目录继续保留，另建干净检出用于安装。



安装器在独立版本目录建立环境，保存 installation-progress.json。重复执行复用已完成环境，包与连接成功后再切换 current。后续命令使用返回的绝对 binary 路径。



安装包包含固定依赖清单，普通 Python 与 uv 路径均安装分析环境。优先使用 uv 创建已验证的 Python 3.13 环境；已有 Python 需为 3.12 或更新版本。安装器的标准输出为 JSON 回执，安装日志写入错误输出。需要回退时使用同一安装器的 -{}-rollback，恢复上一软件版本并核对原任务。

\subsection{验证与复用}


1. project\_\allowbreak{}snapshot(paths=...) 冻结完整研究输入，排除结果。入口、辅助脚本、势和模型均进入依赖。

2. validation\_\allowbreak{}plan 固定组件的输入、科学条件、检查和判据。组件范围为 static、environment、numerics、outputs、analysis；每个条件至少关联一个组件。

3. validation\_\allowbreak{}match 核对输入、环境设置、条件、回执及原始数据，返回直接复用、部分复用或需要验证，列明具体差异。

4. 缺项按文件检查、极小体系贯通、代表性小体系、正式尺寸短运行推进。各层用各自原生输入；尺寸变化影响的组件补测，其余通过 reuse\_\allowbreak{}from 复用。

5. 物理验证用 run\_\allowbreak{}prepare(validation\_\allowbreak{}id=..., stage='preflight') 和记账提交。validation\_\allowbreak{}check 读取本方案已完成作业的数据，核对回收摘要后执行固定检查。

6. 正式计算用 stage='production'。提交和实际派发均重新核对证据。合格计算段通过原生 restart 接续，保存父作业关系。



首份方案使用 environment\_\allowbreak{}capture 读取引擎、启动器及显式外部依赖，并用返回的 runtime\_\allowbreak{}id 绑定方案。登录节点的系统库作为发现记录保存；不同登录节点的库差异不会代替计算节点的判定。记账预验证在实际计算节点保存完整身份及作业编号，回收后与固定检查共同成为可复用证据。正式作业在科研入口前核对已验证的计算节点引擎和运行库；变化时保存具体文件差异。新增插件、容器文件通过 files 指定，原生依赖继续进入快照。旧版仅有登录摘要的回执保留历史，需要补齐实际节点证据。



预验证推荐100核时，实际采用用户确认的 policy.preflight\_\allowbreak{}core\_\allowbreak{}hours，同时保存 preflight\_\allowbreak{}budget\_\allowbreak{}authorization 原话。省略方案预算时沿用此值；任务条件里的估算不会自动成为授权。调度预留按核数乘最长运行时间计算，结束后采用实际记账。累计包含本任务所有方案的失败、取消和在途预留；新建方案不会清零费用或扩大上限。预算不足返回差额与下一步。



run\_\allowbreak{}prepare 返回可供下一次变更使用的任务版本。重复识别比较快照、入口、验证方案、阶段与环境。未派发记录需要接替时使用新 intent 和 supersedes=原run\_\allowbreak{}id，样本身份保持，旧记录和失败保留。已派发或状态未知时先核对原作业。预验证和正式运行分别绑定各自阶段。



种子使用原生 variable seed index 12345；方案声明变量、文件和允许整数范围。匹配仅归一化这些种子，其他输入保持摘要核对。范围由方法依据确定，不从两个端点自动外推。任务名、输出根目录和样本身份由执行记录维护。



\subsection{批量计算与控制}


batch\_\allowbreak{}prepare 为独立样本生成种子不同的快照，并关联有效验证；batch\_\allowbreak{}submit 原子保存整批派发意图。同条件追加20次重复新增预验证作业为零。已验证的不同工况按各自方案建立批次。



batch\_\allowbreak{}get 返回每个样本、种子、状态、证据时间和成本。batch\_\allowbreak{}control 暂停、恢复或停止指定批次。任务控制优先，其他批次保留自己的状态。同一操作编号重试返回原批次；已有样本和种子不能重计独立重复。



validation\_\allowbreak{}control 或停用验证记忆撤销复用资格。相关待派发批次暂停，运行中证据与费用保留；修正后建立新方案。用户说“先讨论”时，Agent 先保存暂停，再进行讨论。正在提交的动作单独对账。



\subsection{实测检查和监视}


check\_\allowbreak{}run 支持文件内容、CSV字段与数值范围、JSON实测量、分段热力学输出、注入前后能量差、全帧轨迹身份和非有限值。回执保留检查版本、测量、阈值、单位及依据、数据摘要。check\_\allowbreak{}get 核对当前证据变化。



同一 Step 的注入前后状态保留在不同 thermo 块。温度统计固定物理时间窗口；漂移固定阶段和参照值。逐帧检查记录实际帧数，原子顺序变化按 ID 对齐。周期几何使用真实盒矩阵与边界，不从缺陷坐标估计盒长。



新检查程序先用 analysis\_\allowbreak{}submit 运行独立正反样例，再由 checker\_\allowbreak{}register 核对相同程序、不同样例和预定结果。checker\_\allowbreak{}check 对新输出应用固定判据；程序变化后重新核验样例。



方案可附带 monitor：节点独立读取增量 thermo 输出，按固定阶段、阈值检测非有限数和能量漂移，保存 .alm-guard.json 并停止异常进程。原生输入按方案写 restart，日志及时刷新。后台保持60秒合并查询和长任务摘要。
