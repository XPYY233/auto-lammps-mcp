# 本地记忆、验证复用与批量研究

本轮依据原始完整计划、W 级联流程审计和用户批准的[能力改进完整计划](APPROVED_CAPABILITY_PLAN.md)实施。本文件维护实现说明；用户批准的全文单独保留，每轮完整读取。对应 [Issue #40](https://github.com/XPYY233/auto-lammps-mcp/issues/40)。

用户说：“参考上次的 W 级联方案，再做20次独立重复，给我平均缺陷数量和误差范围。”Agent 找到过去的任务、原生文件和实测验证，说明直接沿用的内容与新增工作；当前条件已覆盖时直接准备正式批次。用户决定研究目标、科学选择和资源范围。

## 用户流程

自然语言需求 → 本地记忆和资源检索 → 简短科学问答 → 可复用内容与缺项 → 必要验证 → 正式计算或批次 → 监视和分析 → 成果与记忆。

README 的固定安装提示词保持唯一入口。日常工作方法由 skill、MCP 初始化说明和阶段回执提供。每轮只问尚未确定的两三项科学选择，文件和工具细节由 Agent 完成。

## 记忆与成套资源

SQLite 保存当前研究、方法、失败、验证、偏好和结果的索引、版本与来源；原生脚本和数据保持在项目目录。大型轨迹保留原有存储位置。Codex、官方 DSH 和后台共用同一任务服务。

`task_get`、`research_context` 自动返回相关记忆。创建任务、文件修改、输入检查、准备计算和分析的 MCP/CLI 回执附带阶段上下文。`memory_search` 支持中英文同义词、条件关键词和访问范围，`memory_get` 读取完整依据。相似度用于发现工作，`validation_match` 判断验证覆盖。

记录状态包括实际观察 observed、候选经验 candidate、服务实测 verified、停用 disabled。`memory_record` 保存候选、纠正或停用并保留旧版本。服务记录事件和测量；Agent 解释方法与原因。`memory_rebuild` 从保留事件补建索引，保留纠正记录。历史授权不成为新任务许可。

普通研究跨项目检索；作者参考在自己的范围检索；正式 B 只访问本任务记忆，独立执行身份仍按整体计划验收。

`resource_bundle` 关联已有势、配套原生调用文件、元素映射、短程参数、来源、许可、版本和适用条件。`resource_get` 返回成员、版本变化和实际文件状态。W 级联优先核对指定来源中的势及短程组合。普通研究可以学习符合来源和许可要求的作者代码。文件存在、运行完成和科学验证分别记录。

## 验证与复用

1. `project_snapshot(paths=...)` 冻结完整研究输入，排除结果。入口、辅助脚本、势和模型均进入依赖。
2. `validation_plan` 固定组件的输入、科学条件、检查和判据。组件范围为 static、environment、numerics、outputs、analysis；每个条件至少关联一个组件。
3. `validation_match` 核对输入、环境设置、条件、回执及原始数据，返回直接复用、部分复用或需要验证，列明具体差异。
4. 缺项按文件检查、极小体系贯通、代表性小体系、正式尺寸短运行推进。各层用各自原生输入；尺寸变化影响的组件补测，其余通过 `reuse_from` 复用。
5. 物理验证用 `run_prepare(validation_id=..., stage='preflight')` 和记账提交。`validation_check` 读取本方案已完成作业的数据，核对回收摘要后执行固定检查。
6. 正式计算用 `stage='production'`。提交和实际派发均重新核对证据。合格计算段通过原生 restart 接续，保存父作业关系。

预验证默认100核时。累计包含本任务各方案的失败、取消和已派发预留；运行中按预留资源计算，结束后使用实际记账。预算不足返回已用额度和剩余问题。调整预算随方案和用户授权保存到 policy.preflight_core_hours。

种子使用原生 `variable seed index 12345`；方案声明变量、文件和允许整数范围。匹配仅归一化这些种子，其他输入保持摘要核对。范围由方法依据确定，不从两个端点自动外推。任务名、输出根目录和样本身份由执行记录维护。

## 批量计算与控制

`batch_prepare` 为独立样本生成种子不同的快照，并关联有效验证；`batch_submit` 原子保存整批派发意图。同条件追加20次重复新增预验证作业为零。已验证的不同工况按各自方案建立批次。

`batch_get` 返回每个样本、种子、状态、证据时间和成本。`batch_control` 暂停、恢复或停止指定批次。任务控制优先，其他批次保留自己的状态。同一操作编号重试返回原批次；已有样本和种子不能重计独立重复。

`validation_control` 或停用验证记忆撤销复用资格。相关待派发批次暂停，运行中证据与费用保留；修正后建立新方案。用户说“先讨论”时，Agent 先保存暂停，再进行讨论。正在提交的动作单独对账。

## 实测检查和监视

`check_run` 支持文件内容、CSV字段与数值范围、JSON实测量、分段热力学输出、注入前后能量差、全帧轨迹身份和非有限值。回执保留检查版本、测量、阈值、单位及依据、数据摘要。`check_get` 核对当前证据变化。

同一 Step 的注入前后状态保留在不同 thermo 块。温度统计固定物理时间窗口；漂移固定阶段和参照值。逐帧检查记录实际帧数，原子顺序变化按 ID 对齐。周期几何使用真实盒矩阵与边界，不从缺陷坐标估计盒长。

新检查程序先用 `analysis_submit` 运行独立正反样例，再由 `checker_register` 核对相同程序、不同样例和预定结果。`checker_check` 对新输出应用固定判据；程序变化后重新核验样例。

方案可附带 `monitor`：节点独立读取增量 thermo 输出，按固定阶段、阈值检测非有限数和能量漂移，保存 `.alm-guard.json` 并停止异常进程。原生输入按方案写 restart，日志及时刷新。后台保持60秒合并查询和长任务摘要。

温度峰值、熔化、相变和缺陷突变按研究目标解释。确认共同设置缺陷后停用验证，暂停相关后续派发。`artifact_register` 引用实测回执；`completion_check` 核对全部必需成果、当前文件和有效检查。历史自报通过保留为历史声明。分析失败只重做受影响部分。

## 迁移与交接

升级到 schema 2 前保存 schema 1 的一致性副本。完整备份包含记忆与版本、验证、回执、运行、批次、资源和文件；新目录恢复后先对账再接续。回退使用升级前数据库副本和原安装版本，在新目录启动；新版历史保留。两个控制器不能同时提交。

研究 ZIP 保留记忆、验证和批次历史。导入后作为有来源的既有研究记录；跨电脑接续整个服务使用完整备份恢复。

## 实施与验收

| 顺序 | 目标 | 完成条件 |
|---|---|---|
| P0 | 控制和实测核验 | 暂停后无新增派发；错误判据与缺项不能完成 |
| P1 | 记忆、资源和阶段引导 | 新对话找到既有工作、失败及实际文件 |
| P2 | 验证匹配和分级预验证 | 有效条件直接复用；变化只补相关组件；费用累计 |
| P3 | 批量与持续监视 | 20个独立样本复用验证，暂停、重启、回执丢失可恢复 |
| P4 | 安装版本完整流程 | 官方 DSH 新研究、Codex 接续、追加分析、可视化与交接 |

回归覆盖跨项目、新材料与新势、记忆纠正、依赖变化、预算、恢复、成果缺项和备份迁移。真实验收回放 W 失败日志并生成新分析版本。独立用户从自然语言进入，开发者中途技术补充为零。

`research_metrics` 返回研究分母、预验证与正式运行数量、费用及未知记账项、首次派发等待和完成事件。模型、工具与人工介入从宿主原始记录核对。首次研究、复用研究和批量追加分别统计。

原计划的独立 Ni、24项研究至少22项、12项保留任务至少11项、36次故障恢复、八类科学反例、双平台与七天监视继续作为整体交付要求。跨平台安装保留，远程部署不纳入本轮。

方法入口：[累计物理时间](https://docs.lammps.org/fix_dt_reset.html)、[ZBL](https://docs.lammps.org/pair_zbl.html)、[温度定义](https://docs.lammps.org/compute_temp.html)。运行时通过适配器读取实际引擎版本对应文档。
